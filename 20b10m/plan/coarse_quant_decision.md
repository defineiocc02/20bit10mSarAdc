# 粗量化到底放哪：跟踪窗方案的否决与 4+2 亚分区替代

> 结论：**“把 6 bit 粗量化移进 110 ns 跟踪窗”不成立**——输入在跟踪期是动的，粗码必须在采样沿附近 0.31 ns 内定下来。改用 **ΦC0 内 4 bit flash + 2 bit SAR 亚分区**：63 个比较器降到 15 个，面积 0.086→0.028 mm²（含布线省 0.067），时间 6.5 ns < 7.5 ns。

## 1. 跟踪窗方案为什么不行（算术）

| 量 | 值 |
|:---|:---|
| 输入 2 MHz、5 V 幅度时的最大斜率 | $2\pi f A = 62.8$ V/µs = **62.8 mV/ns** |
| 细搜索窗口（5 bit） | ±16 LSB1 = ±156 mV |
| 允许的粗码误差 | ±0.5 粗 LSB = ±8 LSB1 = **±78 mV** |
| 78 mV 对应的时间 | **1.24 ns** |
| 若要求 ±2 LSB1（19.5 mV） | **0.31 ns** |

→ 粗量化必须在采样沿前 **0.3–1.2 ns** 内完成；放在 110 ns 跟踪窗的开头，输入早已走掉 6–60 个 LSB1。**除非输入是直流或极低频，否则跟踪窗粗量化必然错码。**

## 2. 替代：ΦC0 内 4+2 亚分区

```
采样沿 ──► [4 bit flash: 15 cmp, 2.0 ns] ──► [译码+置位 1.1 ns] ──► [2 步 SAR: 2×1.7 ns] ──► ΦC1
```

| 项 | 原方案（63 cmp flash） | **4+2 亚分区** |
|:---|:---:|:---:|
| 比较器数 | 63 | **15** |
| 粗量化精度 | 6 bit（±0.5 LSB6 = 8 LSB1） | 4 bit flash（±0.5 LSB4 = 8 LSB1）+ 2 步 SAR 细化到 6 bit |
| 时间 | 2.0 ns | 2.0 + 1.1 + 3.4 = **6.5 ns** |
| 面积 | 0.086 mm² | **0.028 mm²**（15 cmp + 梯 + 小 SAR 逻辑） |
| 失调要求 | 63 个都要修调 | 15 个，且 4 bit 容差宽 4× |
| 风险 | 极码错码 | 多 2 步 SAR 的建立；已在 6.5 ns 内留 1 ns |

**省 0.058 mm²（含布线 0.067）**，且**不需要**动跟踪窗、不需要改采样时序。

## 3. 对时序的影响

| 相位 | 原 | 4+2 后 |
|:---|:---:|:---:|
| ΦC0 | 7.5 ns（63 cmp + 译码 + 装载） | **7.5 ns（15 cmp + 2 SAR 步 + 装载）**，余 1.0 ns |
| ΦC1 | 15 ns（5 bit 细搜） | 15 ns 不变 |
| ΦRA / ΦC2 | 25 / 37.5 ns | 不变 |

## 4. 落地动作

1. `CmpCoarse6b` 改成 `CmpCoarse4b`（15 cmp），保留 5 bit 修调（每 cmp 一个）。
2. 数字加 2 步 SAR 状态机（约 120 门），复用 `SarLogic1` 的位循环。
3. 面积模型、floorplan、spec_tree 同步：flash 0.086→0.028，core 0.69→0.63。
4. 验证加一条：**4 bit flash 的 ±0.5 LSB4 边界码**（16 个）必须过，不能只看随机码。
