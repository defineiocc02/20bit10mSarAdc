## 5. 必须现在改的一个坑：`ReconWeights` 在 BL-v3 下权重全错

现有实现（29 行）：

```systemverilog
wire signed [25:0] acc = ($signed({1'b0, d1}) <<< 12)
                       + (($signed({1'b0, d2}) - 26'sd1024) <<< 3);
```

三个问题（T05 已指出，这里按 BL-v3 给修正值）：

| # | 问题 | 现实现 | BL-v3 应为 |
|:--|:---|:---|:---|
| 1 | D1 缺中点偏置 | `d1` 直接乘（0..1023 全正） | **`d1 − 512`**（一级 10 判决，中点是 512） |
| 2 | D1:D2 权重比错 | 2^12 : 2^3 = 512 | BL-v3 是 **2^10 : 2^0 = 1024**（因 20 = 10+12−2） |
| 3 | 缺 1/G 增益抽头 | 无 | 名义下可并入权重，但需显式写出 |

**修正后的名义式（22 bit 字，LSB = 0.25 LSB_total）**：

```
acc  = (d1 − 512) × 4096 + (d2 − 2048) × 1
DOUT = 22'h200000 + acc[21:0]
```

边界实测：

| d1 | d2 | acc | 占半量程 |
|:---:|:---:|:---:|:---:|
| 512 | 2048 | 0 | 0.00% ✓ |
| 1023 | 4095 | +2 095 103 | 99.90% ✓ |
| 1023 | 2048 | +2 093 056 | 99.80% ✓ |
| 0 | 2048 | **−2 097 152** | **−100.00% ✗ 溢出 1** |
| 0 | 0 | **−2 099 200** | **−100.10% ✗** |

**结论：22 bit 字只有 0.2% 余量，装不下 d2 的 ±2 LSB1 冗余窗口。** 两个选择：

- **A（推荐）**：保持 22 bit，**加钳位到 ±(2^21−1)** + `OVF` 标志。理由：边角组合（d1=0 且 d2=0）物理上不可能（d1=0 时余差 ≈0，d2 必 ≈2048），钳位只防系数异常。
- **B**：字宽加到 23 bit（LSB = 0.125 LSB_total），`acc = (d1−512)×8192 + (d2−2048)×2`。但 `FramePack`/`SerLvds`/`LVDS` 帧格式全要跟着改。

按投入产出排：

1. **把 `charge_model.py` 当 DAC1 的"真值"用**——它是唯一能逐码算失配/校准残差的东西，而且与已发布结论同源。BL-v3 一级不变，所以它**现在就能用来验证 12 bit DAC2 的分段方案**（改 `UNITS` 与 `_vtop` 的分组即可）。
2. **`model/params.py` 改 2 行 + 跑一遍 `experiments`** —— 半天工作量，能把所有历史结论迁到 BL-v3 口径，且**数字不变**（§1 第 3 条已证）。
3. **RTL 先只改相位窗口和 `NB_D2`（4 行）**，让 `Sar2Ctrl` 能按 20 拍跑；`Sinc2`/`ReconWeights`/`SliceSched` 三处按 §3/§5 重写。
4. **网表先别碰**——DAC1 只有 7 bit（T02 C1），在 PDK 填好之前改网表是白改。**先补 PDK 跑通一个 slice 的 1024 码扫描**，那是 5 分钟就能判死的一件事。

## 9. 20b10mtask 分支：能借什么（2026-11-08 补）

用户指定要看 `defineiocc02/20bit_SAR_ADC_Behaviour_Verification` 的 `20b10mtask` 分支。实际读了它的三棵交付树（task1 调度+DEM+LMS、task2 dither、task3 CAAZ），以下是按 BL-v3 判定的可借项。

### 9.1 最高价值：`task1/rtl/slice_scheduler.sv`（约 150 行）

**这正是我们 `SliceSched.sv` 缺的那一层。** 对比：

| 能力 | 我们的 `SliceSched.sv`（48 行） | task1 的 `slice_scheduler.sv` |
|:---|:---|:---|
| 选片 | `mask8(base)`，硬编码 8 片 | `eligible_i & ~acq_mask`，按环形序位取前 8 |
| 资格不足 | **无**（假设永远够） | `stall_o` 拉高一拍，**所有状态保持** |
| 有序 ID | **无**（只有掩码） | `acq_ids_o[39:0]` = 8 slot × 5 bit |
| 样本 ID | **无** | `acq_sample_id_o` / `conv_sample_id_o` 32 bit |
| 组晋升 | `base += 8 mod 18` 轮换 | 上一采集组**整体晋升**为转换组 |
| 事件输出 | 无 | `slot_accepted_o` 单拍脉冲 |

它解决我们两个真问题：

1. **D42 的 `POS2SLICE` 槽位缺口**——我们原打算用一张静态 8×5 表，它用的是 `eligible_i` + 环形前缀，天然支持"坏片退出、备片顶上"，不需要重写映射表；
2. **换备片后失效的是 8 片还是 16 片**——它的 `slot_accepted_o` + 样本 ID 让"哪一帧用了哪 8 片"可追溯，而我们的掩码做不到（`MON` 只截了 `base[3:0]`，T05 的 N3）。

**借用方式**：取 **固定模式（`shuffle_i = 0`）** 那半边——从物理 ID 0 环形扫描、按序位选 8 片。它的随机轮转（LFSR + 取模游标）**我们要删掉**，因为版图已证伪"片间洗牌"（T04 C2：66 ppmFS ≈ 98–138 LSB_total）。`eligible_i` 保留，用于良率重映射。

**改动量**：约 20 行（删 shuffle 分支、把 `advance_i` 接到我们的 `swap`、5 bit ID 对齐 18 片）。

### 9.2 中价值：LMS 训练纪律（`task1/evidence/bridge_lms/`）

他们的验收口径值得直接抄：

> "两路使用同等训练预算、同一留出输入；**不把使用 DEM 激励训练的系数冒充无 DEM 基线**。"

这正是我们 144 系数校准要防的坑——我们在 `cal_residual` 里已经用了"有限样本、固定 n_avg"的口径，但**没有做独立留出集**。建议补：训练集与验证集分开，报告的 INL 必须在留出集上。

### 9.3 一个重要的层次区分：片内 DEM ≠ 片间洗牌

我们取消的是**片间洗牌**（18 片之间换角色）。task1 的 `fig11_dem.sv` 做的是**片内电容级 DEM**（15 个 2C 单元轮转 + 16 个 1C 单元的 B4 分配）——**这是两个不同层次，前者被证伪，后者未被评估。**

但要注意他们的数据：同一失配池下 DEM 让 SFDR 从 91.76 → 98.03 dB，**同时 SNDR 从 81.05 → 78.09 dB**（确定性误差转成变化噪声）。所以片内 DEM 也是双刃剑，不是免费收益。

**结论**：片内 DEM 列为 P2 可选项，判据是"SFDR 收益 > SNDR 损失"，不并入 BL-v3。

### 9.4 低价值/不可用：CAAZ（`task3/`）与 dither（`task2/`）

**CAAZ 与 10 MS/s 直接冲突**——task3 自己写明：「两点配对……**将输出速率从 10 MS/s 降到 5 MS/s**」。

我们的 10 MS/s 靠 2 相交织实现（每相 5 MS/s）。若每相内部再做 CAAZ 偶奇配对，每相掉到 2.5 MS/s，两相合起来只有 5 MS/s。**速率减半，与项目目标冲突。**

→ CAAZ 只能作为 P2 备选（若允许 5 MS/s），或用于"诊断模式"（跑一次看 AZ 噪声占多少）。

**dither** 的结论同样要打折：task2 实测 dither 开/关的 SFDR 是 127.265 → 128.554 和 128.253 → **127.126**（第二项退化），DNL RMS 只从 0.1310 → 0.1288。**改善集中在静态码密度（零宽码 678k → 0），不改善 SNDR**，且满幅会拒绝 0.86% 的输入。

→ 我们的 BL-v3 LSB2 = 1.0 LSB_total（不是他们的 5.12），零宽码问题本来就轻，dither 优先级降到 P2。

### 9.5 一个数字交叉验证（这条最值钱）

task1 的判据原话：

> "12 位 ADC2 的输入等效总窗口若**不超过 39.06 mV**，其理想步长不大于一个 20 位 LSB。"

我们 BL-v3 的 DAC2 量程 = **39.0625 mVpp**，LSB2 = 9.5367 µV = **1.000 LSB_total**。**正好命中这个临界条件。**

而他们为了容纳 2%/3% 失配，实际用了 **±100 mV 窗口（步长 48.83 µV = 5.12 LSB20）**，靠 8× 平均 + dither 才补回分辨率。

**这说明两件事**：

1. 我们选 39.06 mV 是"刚好够、不浪费"——不需要靠平均补；
2. **代价是余差窗口只有 ±2 LSB1**，对 DAC1 建立误差与比较器失调的容忍度比他们紧 2.6 倍。

用他们的实测数反推我们的余量：2% 失配未校准 INL = 901.9 LSB20 × 9.5367 µV = 8.60 mV = **0.88 LSB1**；3% 时 = 1351.5 × 9.5367 µV = 12.9 mV = **1.32 LSB1**。

> **两者都在 ±2 LSB1 窗口内。** 这是对 BL-v3"冗余 2 bit"选择的一条外部实证支持（拓扑不同，只作量级参考）。
