## 2. 各项细节

### 2.1 调度器（固定模式）

```
帧 0: 采集 [0..7]        转换 [-]
帧 1: 采集 [8..15]       转换 [0..7]
帧 2: 采集 [0..7]        转换 [8..15]
```

- 每片在 12 帧里被用 **5 次**（16 片均分，2 片备用从不使用）；
- **stall 逻辑正确**：坏 2 片（剩 16）仍不 stall；只剩 7 片时**全部 stall**且状态保持；
- `shuffle=True` 分支（LFSR 随机游标）保留但**BL-v3 不用**——版图已证伪片间洗牌。

**在 BL-v3 的用法**：只取固定模式。`eligible` 用于良率重映射（坏片退出、备片顶上），这正是 D42 的 `POS2SLICE` 想解决但没解决的事。

### 2.2 dither 字：numpy 可用，我的 PRBS 有 bug

| 字源 | 131072 字的卡方（df=63，临界 99） | 判定 |
|:---|:---:|:---|
| numpy PCG64 | **61.9** | ✅ 均匀 |
| 我的 PRBS31 实现 | **403.7** | ✗ 不合格 |

**PRBS 的 bug 定位**：单看 1 位，比例是 **0.4868**（应 0.5），偏离 **12σ**。这不是"字间相关"，是**位本身就不均匀**——说明 taps 或移位方向有错（我按 `x³¹+x²⁸+1` 取 bit30 XOR bit27，左移注入）。

**处置**：dither 的结论用 numpy 版出，PRBS 版标注"硬件可实现形式，本实现待核对"。这不影响机制验证，但**如果要照它写 RTL，必须先修**。

### 2.3 Fig.19 七片分配

| 字 D6..D1 | m | L | u | 总扰动 |
|:---|:---:|:---:|:---:|:---:|
| 000000 | 0 | 0.00 | 0 | 0.00 |
| 000111 | 7 | 1.00 | 0 | 1.00 |

范围 0–8 个一级 LSB。**七片示例，不能把 `/7` 改成 `/8` 当八片结论**（task2 README 明确警告）。

### 2.4 CAAZ

```
两笔输入相同：
  AZ 完全共享 (share=1) -> 输出残余 0.00 µV
  AZ 各自独立 (share=0) -> 输出残余 14.33 µV   (理论 20/√2 = 14.14)
```

与 task3 的"独立 AZ 19.13 → 理想共享 13.68 µV"同量级（差在它们的 AZ 噪声取 20 µV RMS）。

**硬约束**：输出速率 **10 → 5 MS/s**。BL-v3 的 10 MS/s 靠 2 相交织，再叠 CAAZ 会掉到 5 MS/s → 只能作诊断模式。

## 4. 还没做的（这是下一步的关键）

这三项现在**只是独立模块 + 自检**，还没有接进 `simulate_v2`。要测它们的真实效果，缺一个前提：

> **v2 的 DAC1 目前是理想的**，没有逐码失配。而 dither 和 DEM 的全部作用对象就是"失配"——没有失配，它们的效果恒为零。

所以顺序必须是：

1. **把 `charge_model` 的 1024 码失配接进 v2**（让 DAC1 有真实 INL/DNL）；
2. 再开 dither / DEM，看零宽码与 SFDR 改善多少；
3. 那时才能判断"我们的 1.0 LSB20 架构到底需不需要它们"。

**在做好第 1 步之前，任何"dither 提升 X dB"的数字都不成立**——包括我上面引用的前版数据（那是 5.12 LSB20 架构下的）。

## 5. 接进 v2 之后的实测（4096 点，100.1 kHz）

先把 `charge_model` 的 1024 码失配接进 v2（`inl_lsb1` 参数），再开 dither：

| 配置 | SNDR | SFDR |
|:---|:---:|:---:|
| ① 理想 DAC1 | 100.60 | 123.8 |
| ② 失配（σu=0.2%，未校准） | **94.36** | **103.6** |
| ③ 失配 + dither ±0.5 LSB1 | **94.35** | **103.6** |
| ④ 失配 + dither ±0.25 LSB1 | 94.35 | 103.6 |
| ⑤ 校准后残差 | **100.63** | **123.8** |

### 三个结论

1. **dither 对 SNDR/SFDR 一点用都没有**（94.36 → 94.35，差 0.01 dB）。这不是实现问题——理论如此：**dither 只重新分布量化噪声，不减少总噪声功率**。它改善的是 DNL 与零宽码，而这两个在我们的架构里不是问题（LSB2 = 1.0 LSB20，每码都有真实台阶）。
2. **校准才是有效手段**：94.36 → 100.63（**+6.3 dB**），完全恢复到理想水平。
3. **dither 本身不伤指标**：无失配时 ±0.5 LSB1 的 dither 给出 100.58（对比 100.60）——说明去扰逻辑是对的。

### 这个结论与前版为什么相反

前版（20b10mtask）必须做 dither，因为它的 **DAC2 步长 = 5.12 LSB20**，2²⁰ 个码里 **76.5% 是零宽码**（实测 802,491 个）。那种情况下不加 dither，码密度表根本填不满。

我们是 **1.0 LSB20**，零宽码问题不存在。**所以 dither 是前版的必需品、我们的可选项。**

## 6. 我在这一轮写错的第五个 bug（记录）

| # | Bug | 症状 |
|:--|:---|:---|
| 5 | **dither 去扰方向反了** | 无失配时加 dither 也让 SNDR 从 100.6 掉到 55.6（掉 45 dB） |

根因：二级编码的是 `resid_ideal − d`，所以数字端要**加回** `d`，我写成了减。修完后 dither ±0.5 LSB1 对理想电路的影响是 0.02 dB。

**连同前四个（SAR 位序、双极性平移、窗口多乘 G、偏移二进制），这份模型一共错了五次。** 每次都不是"跑不通"，而是"跑得通但数字错"——所以理想锚点（122 dB / 2.75 µV）是唯一的守门人。
